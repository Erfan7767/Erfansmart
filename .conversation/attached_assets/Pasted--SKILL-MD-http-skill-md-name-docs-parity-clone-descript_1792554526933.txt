

"[[SKILL.MD](http://skill.md/)] name:docs-parity-clone description: >- Clone a documented product or a whole website — API contract, every page, every asset, every pixel — with parity proven by script instead of asserted in prose. Use when asked to reproduce a service or a site from its public surface, or when a "100% complete" claim has to be measured. Covers both tracks — harvest docs and build a contract harness with parity gates and a regression ledger, and harvest pages and audit coverage and visual diffs with defect rounds. Ends in an honesty list, not a slogan. license: MIT Docs → parity clone A repeatable way to rebuild a product from its published surface and prove the rebuild matches. The output of one round is never an opinion: it is a script that fails, or a number in a table. Extracted from a real build that ran 52 rounds against a 37-operation API and a 393-file site (ErfanAgent, [REVERSE.md](http://reverse.md/) §1–60). Workflow text 0. declare ── what "done" means, in numbers, before writing code 1. harvest ── scripts/harvest_[docs.py](http://docs.py/) → re/docs/, re/openapi.json (contract) scripts/harvest_[site.py](http://site.py/) → re/site/, site-inventory.json (site) 2. skeleton ── every operation exists; every page exists; audit/coverage: 0 missing 3. harness ── scripts/schema_[walk.py](http://walk.py/) → parity: every documented field measured scripts/asset_[audit.py](http://audit.py/) → coverage: every reference resolves 4. rounds ── references/[03-round-loop.md](http://03-round-loop.md/): measure → fix → pin → document → gate 5. gates ── scripts/[gate.sh](http://gate.sh/): all gates green, in one command, on a clean clone 6. fidelity ── scripts/[shot.py](http://shot.py/) + visual_[diff.py](http://diff.py/): same pixels, same widths, or a number that says how far off and where Round 0 decides the vocabulary: the error envelope, the enum values, the page shell, the auth classes, the widths you will be judged at. Everything after that is arithmetic against it. Non-negotiables The reference is data, and it is stored. Docs pages, OpenAPI fragments, every site page and asset — fetched into the repo with a manifest. You diff against a snapshot, not memory. Optionality is read from prose, never guessed. A field is optional because its description says "only present when…"; otherwise its absence is a failure. Same rule for pages: a page is "not part of the surface" only when the inventory says so. Ask the artefact, not the source. For a site, ask the server for every href and src on every page. For the API, ask the running build for every documented field. Source review does not count as evidence. Three gates, three questions. selfcheck: does the behaviour work? parity: does the shape match? audit: is anything missing — operations, pages, links, CSRF, escaping, docs/code drift? Add coverage and visual for the site track. Each gate has its own exit code. A gap is closed only when a probe fails before the fix and passes after. Write the probe first; it is the only evidence that survives a refactor. Unfixable ≠ unmentioned. Anything that cannot match — no CDN, no cloud browser, no per-App ownership, a placeholder price — goes in [HONESTY.md](http://honesty.md/) with the documented sentence it deviates from. A deviation with no entry is a defect; an entry with no deviation is decoration. Numbers in docs are generated, not typed. Test counts, operation counts, page counts, and parity rows come out of the tools; the audit fails when a README disagrees with the code.
